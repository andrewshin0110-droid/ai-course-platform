# 🎓 長庚大學 ICGU 智慧選課與成績管理平台 (AI-Powered Campus Platform)

## 📌 專案源起與畢業生自述
本專案為長庚大學資管系的畢業專題作品。設計初衷是為了解決校園教務系統在「選課資訊過載、空堂篩選僵化、以及論壇社群評論失控」等現實痛點。

本專案由團隊協作開發。在團隊中，**我主要負責核心的「AI 數據智能模組」與「核心教務 CRUD 演算法」的後端研發**。在開發過程中，我除了鞏固扎實的資料庫多表聯結邏輯外，更致力於將**機器學習（ML）與生成式 AI（LLM）無縫落地到傳統 Web 應用中**。這段專題經驗不僅培養了我與前端、資安夥伴對接 API 規格的團隊協作能力，更讓我具備了用技術解決實際問題的工程師思維。

## 💡 個人主導技術亮點與軟體工程實踐

### 1. 機器學習社群防禦：惡意言論即時攔截網閘
* **面臨痛點**：開放式課程論壇極易出現非理性謾罵或人身攻擊（如「這個老師很白癡」），導致校園社群生態惡化。
* **解決方案**：我於評論提交的後端核心邏輯中，實作了基於自然語言處理（NLP）的文字過濾機制。在資料準備寫入資料庫前，將文本送往語意分析分類器進行即時審查。
* **真實成果**：具體成果請參考專案隨附之 **`螢幕擷取畫面 toxic-speech-blocked.png`**。當使用者輸入不當言論並嘗試點擊「提交評論」時，後端分類器判定有害信心值超標，立即切斷 SQL 寫入程序，回傳錯誤並由前端觸發警告彈窗，實作主動式內容安全控制（Content Security）。

### 2. 大型語言模型應用：結構化評論智慧總結
* **面臨痛點**：熱門課程往往累積了數百條學長姐評價，資訊高度過載，學生在選課排課時難以快速抓到重點。
* **解決方案**：我引入生成式 AI（Generative AI）LLM API，並透過**結構化提示詞工程（Prompt Engineering）**，強制模型必須以「正方觀點（優點）」、「反方觀點（缺點與挑戰）」與「中立選課建議」三大維度進行提煉，有效抑制 AI 幻覺。
* **工程思維（成本與排版控制）**：具體成果請參考專案隨附之 **`螢幕擷取畫面 ai-summary-demo.png`**。介面貼心地支援使用者自訂「總結字數限制」。後端會動態將此數值代入 Prompt，並同步調節 API 的 `max_tokens` 參數。這不僅**優化了 API 呼叫成本**，也有效**防止前端排版溢出**。

### 3. 多條件組合動態課程搜尋引擎 
* **動態 SQL 拼接**：因應學生交叉篩選（開課序號、教師編號、星期等）的高度彈性，後端採用經典的 `WHERE 1=1` 技巧，動態拼裝 SQL 指令，自動忽略未填寫的空白欄位，維持代碼的高擴充性。
* **時段區間映射演算法**：為了解決校園非標準「課表節次（1~14節）」與資料庫實體時間的比對衝突，我利用 PHP 雜湊表（Hash Maps）建立節次與 24 小時制時間的對應關係。利用 SQL 字串大小比對特性，實作出了極具實用價值的**「空堂時段複合篩選功能」**。

### 4. 高效歷年成績查詢與異步資料導出 
* **多表聯結優化 (Triple-Table JOIN)**：為避免多次單表查詢帶來的資料庫 I/O 損耗，手寫高效 SQL 將 `修課`、`開課` 與 `課程` 三表進行關聯查詢，在單次 Query 內即時補齊學分、必選修屬性與通識領域等元數據。
* **防禦性程式設計**：時序上利用 `ORDER BY` 確保正確性，前端輸出則全面封裝 `htmlspecialchars()` 進行 HTML 實體編碼，徹底阻絕儲存型跨站指令碼（Stored XSS）攻擊。並與下載腳本配合，實作歷年修課 CSV 檔一鍵下載。
